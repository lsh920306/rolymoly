# 롤리몰리

`app.py`를 진입점으로 사용하는 Streamlit 클랜 운영 앱입니다. 기존 Community Cloud의 시작 파일을 유지할 수 있도록 `streamlit_app.py`도 같은 화면을 실행합니다. 기존 ZIP은 운영 정책의 참고 자료로만 사용했고, 화면과 데이터 처리는 새로 작성했습니다. 이번 범위에서 멸망전은 제외했습니다.

가입·로그인과 카카오톡 명단 확정의 최신 기준은 [현재 운영 흐름과 검토](CURRENT_FLOW.md)입니다. 이번 가입 화면 간소화·v7 랭크 저장·입찰 응답성 개선의 구현과 검증 상태는 [전체 구현 보고서](docs/ROLYMOLY_IMPLEMENTATION_REPORT.md)를 따릅니다. 과거 운영·정책 추출 문서는 비교 이력으로 보존합니다.

이번 DB 예외 처리·주최자 제어·유찰 재경매·명단 붙여넣기·가독성 수정 내역은 [추가 개선 보고](DB_IMPROVEMENTS_REPORT.md)에 정리했습니다.

이번 Riot 연동·개인 프로필·경매 설정 팝업·실제 ID 체험 명단 변경은 [Riot 연동 및 체험 검증 보고](RIOT_API_REPORT.md)를 기준으로 확인합니다. 이전 DB 개선판의 366개 테스트·58단계 리허설과 이번 변경의 검증을 구분하며, GitHub·Cloud 배포 및 실제 여러 기기의 화면 검수는 별도입니다.

팀장 선택·참가 팀 카드 변경 당시 **고유 테스트 575개 전체 통과·누락 0개·소스 135개 해시 일치**를 확인한 이력이 있습니다. 최초 병렬 실행의 보조 모듈 import 경로 오류 3개는 제품 소스 변경 없이 `PYTHONPATH=tests`로 누락된 9개를 재검증했고, 통과 메서드 ID를 전체 발견 목록과 대조했습니다. 현재 검수 Cloud 앱은 배포되어 있으며, 이번 추가 변경의 전체 회귀·재배포·브라우저 검증은 이 과거 결과와 구분합니다. [당시 결과](test-artifacts/deployment-final-verification.json), [배포 검증](DEPLOYMENT_VERIFICATION_REPORT.md), [현재 검증 상태](docs/ROLYMOLY_IMPLEMENTATION_REPORT.md)

카드 변경 전 **565개**, 그 이전 **508개** 전체 회귀와 회원 목록 화면 40개·백엔드 8개·추가 예외 검수 7항목·Supabase 60단계는 각 시점의 과거 검증 근거로 보존합니다. [이전 변경·검증](RIOT_API_REPORT.md)

사용자의 삭제 요청에 따라 과거 체험 DB·임시 자료·중복 검수 파일 **552개를 영구 삭제**했습니다. 현재 체험 명단 22명, Riot 스냅샷, 운영·정책 문서 및 비밀 설정은 보존했습니다. [현재 정리 내역](CLEANUP_REPORT.md)

회원·계정·티어·내전·경매·점수·업적은 Supabase DB에서 관리합니다. 구글시트 연동과 기존 회원 자료 가져오기는 사용하지 않습니다. 최신 전체 회귀, 회원·일반내전·경매 리허설 결과와 실제 브라우저·Cloud에서 남은 확인은 [시나리오별 QA 보고](QA_SCENARIOS.md)에 구분했습니다.

## 실행

이 작업 공간에는 `.venv`와 필요한 패키지가 준비되어 있습니다. `run.bat`를 더블 클릭하거나 PowerShell에서 실행하세요.

```powershell
.\.venv\Scripts\python.exe -m roly.server
```

실행기는 서버의 경매 마감 처리 작업을 먼저 시작하고 `app.py`를 실행합니다. 화면만 직접 실행하려면 아래 명령을 사용할 수 있습니다. 실제 경매 운영에는 위 실행기를 사용하세요.

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

새 PC와 Community Cloud는 검증한 **Python 3.11**에 맞춥니다. 새 PC에서는 다음 명령을 사용합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m roly.server
```

공식 [Streamlit 설치 가이드](https://docs.streamlit.io/get-started/installation)의 가상환경·실행 방식을 따릅니다. `yourscript.py`는 예시 파일명이며 이 프로젝트에서는 `app.py`입니다. `streamlit skills`는 개발 에이전트용 가이드 설치 명령이고 앱 실행 명령은 아닙니다.

배포 모드는 `[app] environment`로 정합니다. **`test`와 `production`은 공용 Supabase만 사용하고 Workspace·체험 계정·체험 데이터 생성을 차단합니다.** `test`에는 ‘검수용’ 배지가 표시됩니다. 모드를 생략하면 `production`이며, 잘못된 값이나 공용 DB 설정 오류는 실행을 중단합니다. 로컬 체험은 명시적인 `local` 모드에서만 사용합니다. Cloud Secrets 입력 순서는 [배포 안내](DEPLOYMENT.md#검수-앱의-cloud-설정)에 있습니다.

실행기를 사용하면 경매 화면을 열어 두지 않아도 서버가 실행 중인 동안 마감과 다음 선수 진행을 처리합니다. 서버를 종료하면 작업도 멈추며, 다시 실행하면 저장된 상태와 마감 시각을 기준으로 이어갑니다. 로컬 실행은 `127.0.0.1`을 사용하고, 공유 DB를 사용하는 검수 앱은 Community Cloud에 배포되어 있습니다. Cloud 절전 중에도 실행되는 독립 마감 워커는 아직 없습니다.

## Supabase 연결과 운영 계정

Supabase PostgreSQL 17을 운영 저장소로 사용합니다. 현재 코드는 비공개 `rolymoly` 스키마 버전 7을 지원합니다. 개인 가입·비밀번호 복구, 회원·경기 당시 정보, 점수·생성 영수증, 내부 메모와 Riot 작업·호출 한도를 같은 DB에서 관리합니다. 현재 솔로·자유랭크는 `member_ranks`의 `SOLO`·`FLEX` 행에 각각 저장하고, 프로필 이미지·숙련도는 `riot_profiles`에 저장합니다. 기존 앱 DB를 보존하는 구조 업그레이드와 외부 회원 자료 가져오기는 별개이며, 구글시트를 운영 저장소로 사용하지 않습니다. 운영 연결 오류는 시작을 중단하고, SQLite는 명시적인 로컬 개발·체험·검증에만 사용합니다.

`.streamlit/secrets.toml`의 **Connect → Session pooler** host·user·DB 비밀번호를 앱과 검사 도구가 함께 사용합니다. 실제 파일은 Git/소스 ZIP에서 제외합니다. `scripts/check_supabase.py`는 읽기 전용 진단이며, `scripts/prepare_storage.py`는 최초 연결 시 운영 스키마 준비에 사용했습니다. 현재 코드의 지원 버전과 실제 운영 스키마 적용 상태는 구분합니다. 연결 설정과 Cloud Secrets 입력은 [배포 안내](DEPLOYMENT.md#supabase-연결-정보-입력)를 참고하세요.

**최초 관리자 설정은 배포자가 확인해야 합니다.** 새 프로젝트에서 최초 관리자 생성이 필요합니다. Supabase 운영 공간에서는 방문자에게 최초 관리자 생성 폼을 보여주지 않습니다. 비공개 터미널의 아래 명령으로 앱 관리자 계정을 만들며, 비밀번호는 화면에 표시되지 않고 Supabase DB 비밀번호와 별도로 정합니다. 이미 관리자가 있으면 추가 생성하지 않습니다.

```powershell
$env:ROLYMOLY_DATABASE_TARGET = "supabase://rolymoly"
.\.venv\Scripts\python.exe -X utf8 scripts\create_admin.py
```

PostgreSQL 리허설은 회원·로그인·일반내전과 경매·예외 흐름을 나누어 별도의 임시 QA 스키마에서 진행하고 검수 자료를 정리합니다. GitHub·Community Cloud의 기존 검수 배포와 이번 수정본의 재배포 상태는 [전체 구현 보고서](docs/ROLYMOLY_IMPLEMENTATION_REPORT.md)에 구분합니다. 실제 PostgreSQL에서 워커 강제 종료·재시작·두 워커의 중복 정산 방지를 검증했지만, Cloud 절전 중에도 실행되는 독립 DB 마감 워커는 후속 작업입니다.

## 이용 순서

1. 검수·운영 배포는 **운영 공간**만 제공합니다. 모든 브라우저가 설정된 동일 Supabase DB에 실제 계정으로 가입·로그인하며, 체험 계정 전환과 체험 데이터 생성은 사용할 수 없습니다. `test`라는 설정이 별도 DB를 자동으로 만들지는 않으므로 검수에 사용할 Supabase 프로젝트를 배포자가 지정합니다. **Workspace → 체험 공간**은 로컬 개발에서만 표시됩니다.
2. 최초 관리자 생성 후 **운영 공간 → 계정 로그인**에서 로그인합니다. 로그인 폼은 펼쳐진 상태로 표시됩니다. 미리 정해진 관리자 비밀번호는 없습니다. 로컬 SQLite만 사용하는 경우에는 운영 공간의 기존 최초 관리자 설정 폼을 사용할 수 있습니다.
3. **회원가입**에서 로그인 아이디·비밀번호와 확인·Riot ID·주 포지션·부 포지션을 입력하고 운영 절차 확인을 체크합니다. 현재 티어·LP·신청 메시지는 가입 화면에서 입력하지 않습니다. **운영 관리 → 가입 승인**에서 기본점수를 확인해 승인하면 같은 계정을 사용하며, 보완 요청은 **내 계정**에서 확인합니다. 승인 회원은 **본인 프로필 또는 내 계정 → 닉네임 변경**을 사용할 수 있습니다. 로그인 아이디·회원 연결·점수·업적·포지션·클랜 티어와 과거 기록은 유지하고, 다른 Riot ID로 바뀌면 이전 API 정보를 비운 뒤 필요할 때 **갱신하기**로 조회합니다. 관리자는 **회원 → 회원 정보 수정** 또는 **운영 관리 → 회원·점수**에서 주·부 포지션과 클랜 티어 등을 수정합니다. 과거 신청 메시지와 내부 운영 메모는 별도로 보존합니다.
4. **일반내전**에서 10명·20명을 정하고 **참가 회원 검색·선택** 또는 **카카오톡 명단 붙여넣기**로 회원을 고릅니다. 붙여넣기는 DB의 정확한 Riot ID를 찾아 미등록·중복·미승인 회원을 먼저 표시하며, 회원의 티어·포지션 원본을 덮어쓰지 않습니다. 아래 배정표에서 필요한 선수의 포지션만 수정한 뒤 **팀 편성하고 내전 만들기**를 누릅니다. **경매 만들기**는 생성 대화상자에서 일정·설명과 4·6·8팀 규모를 정합니다. 참가자 등록에서도 같은 검색·배정표를 사용하고, 명단 확정·팀장 지정·경매 준비를 순서대로 진행합니다. 앱에는 출석 기능을 두지 않습니다.
5. 실시간 경매를 마치면 같은 경매 페이지에서 팀 포지션을 확인하고 대진표를 생성·확정합니다. **경기 기록 → 경매**에서 실제 경기 결과를 입력하고, 모든 경기가 끝나면 경매를 종료합니다. 일반내전 결과는 같은 메뉴의 **일반내전** 탭에서 입력합니다.

승인된 모든 회원이 일반내전·경매를 개설하고 본인이 만든 내전을 진행할 수 있습니다. 관리자는 회원·계정·정책과 전체 내전을 관리합니다. 참가 신청은 카카오톡에서 받고 개설자가 명단을 확정합니다. 이 경매에서 팀장으로 지정된 회원만 본인 팀으로 입찰하며 다른 회원도 전체 경매를 함께 관전합니다. 로그인하지 않은 방문자는 공개 현황 조회·가입 신청만 할 수 있습니다.

운영진도 승인된 개인계정에 진행자·관리자 역할을 부여해 사용합니다. 관리자 화면에는 별도 회원계정 발급이나 회원 재연결 폼을 두지 않습니다. 탈퇴하면 운영 역할도 사용할 수 없고, 마지막 활성 관리자는 해제하거나 탈퇴 처리할 수 없습니다. 탈퇴 전 진행 중인 내전과 팀장 여부를 확인하며, 복귀는 최초 승인과 구분합니다. 승인 이력이 있으면 활동 상태로, 거절된 미승인 신청자는 다시 보완할 수 있는 상태로 돌아갑니다.

## 로컬 개발에서 경매 체험하기

이 절은 `local` 모드 전용입니다. 검수 앱 `test`와 정식 운영 `production`에서는 아래 체험 계정·공간을 만들 수 없습니다. 로컬 개발용 SQLite를 명시하려면 다음처럼 실행합니다.

```powershell
$env:ROLYMOLY_APP_ENVIRONMENT = "local"
$env:ROLYMOLY_DATA_DIR = "$PWD\.data\development"
$env:ROLYMOLY_DATABASE_TARGET = "$env:ROLYMOLY_DATA_DIR\rolymoly.sqlite3"
.\.venv\Scripts\python.exe -m roly.server
```

**체험 공간 → 체험 계정**에서 **체험 운영진 · 관리자**, **1팀~4팀 팀장**, **일반 참가자**를 선택합니다. 선택할 때마다 실제 계정 로그인과 회원 연결을 확인합니다. 임의로 세션 권한만 바꾸지 않습니다. 계정 선택이 보이지 않는 예전 체험 세션에서는 **새 체험 공간 만들기**로 새 데이터를 준비하세요.

현재 체험 데이터 버전은 **5**(`DEMO_DATA_VERSION`)이며 코드가 지원하는 PostgreSQL 스키마 버전 **7**과는 별개입니다. 체험 명단 22명 중 성공한 21명의 공개 스냅샷에 솔로·자유 티어와 숙련도 상위 5개를 보존하고, 조회 실패 1명에게 가짜 API 정보를 채우지 않습니다. 체험 API 추가 조회의 별도 옵션은 `[riot] allow_demo=false`가 기본이며, 검수·운영 배포에서는 이 값을 유지합니다.

체험 계정 비밀번호는 매번 무작위로 만들고 현재 브라우저 세션에만 보관합니다. 운영 공간에는 테스트 계정이나 고정 비밀번호를 추가하지 않습니다. 다른 브라우저나 별도 Streamlit 세션에서는 다른 체험 DB를 사용하므로, 이 체험은 한 화면에서 계정을 바꿔 진행합니다.

1. **체험 운영진 · 관리자**로 **경매 → 주말 경매 · 4팀**을 선택합니다. 20명 명단과 네 팀장이 확정된 준비 상태입니다.
2. **경매 설정하기** 팝업에서 각 팀의 시작 예산과 **선수별 입찰 시간**을 설정한 뒤 **경매 설정 저장 → 경매 시작**을 누릅니다. 시간은 5·10·15·20·25·30초 중 선택하며 기본은 10초입니다. 새 유효 입찰 시 5초를 더하되 **선택한 시작 시간을 넘지 않습니다**. 10초 설정에서는 1→6초, 2→7초, 7→10초입니다. 계정 전환을 연습하려면 30초를 선택할 수 있습니다.
3. **체험 계정**을 **1팀 팀장**으로 바꾸고 흰 입찰 카드에서 포인트를 정한 뒤 버튼에 표시된 금액(예: **10 P 입찰하기**)을 확인해 누릅니다. 증액과 직접 입력은 브라우저에서 즉시 바뀌며 서버 재실행을 요청하지 않습니다. 제출할 때 선수·금액·UUID가 고정되고, 접수 확인 중에는 새 입찰을 막습니다. **2팀 팀장**으로 바꿔 현재 최고가보다 높은 금액을 입찰하면 경쟁 입찰도 확인할 수 있습니다. 사용 가능한 포인트를 넘는 입찰은 거부되며 중복·거절된 요청은 마감을 연장하지 않습니다.
4. 오른쪽 상단 **스피커 아이콘(입찰 소리 켜기)**을 한 번 누르면 새로 접수된 입찰에 효과음이 울립니다. 음량은 0~100%로 조절하며 0%는 무음입니다. 마감 후에는 낙찰팀 잔여 포인트에서 금액을 차감하고 **3초 동안 다음 선수를 준비**합니다. 준비 중에는 입찰할 수 없습니다. **일반 참가자**는 관전 화면이며 개설자·관리자는 진행 화면의 같은 위치에 유지되는 **일시정지·재개** 버튼을 사용합니다.
5. 네 팀에 남은 선수를 배정합니다. 각 팀장이 탑이므로 팀마다 정글·미드·원딜·서포터 한 명씩 확보하면 됩니다. 현재 라운드의 모든 선수가 끝나고 유찰자가 남았을 때만 **유찰 재시작**을 사용합니다. 유찰 선수 전체를 다시 섞어 저장하고 3초 준비 후 다음 라운드를 시작합니다. 아직 현재 라운드가 진행 중이면 유찰 선수를 앞당겨 끼워 넣지 않습니다.
6. 경매가 끝나면 **경매 완료** 화면으로 자동 전환해 전체 팀장·팀원·낙찰가·잔여 포인트을 카드로 표시합니다. 운영진으로 **팀별 포지션 확인·수정 → 대진표 생성 → 대진표 최종 확인**을 진행합니다. 각 팀 5명과 포지션별 한 명이 필요합니다.
7. **경매 결과 보기** 또는 **경기 기록 → 경매**로 이동해 준비된 토너먼트의 준결승 두 경기와 결승 결과를 저장합니다. **우승 확정하고 경매 종료**를 누르면 실제 우승팀 다섯 명에게 고양이 한 개씩 지급됩니다. **회원** 또는 **회원별 기록**에서 확인할 수 있습니다.

경매 입찰 포인트는 팀 예산입니다. 회원 전력점수에 더하지 않습니다. 경매 결과를 저장하는 동안 전력점수는 그대로이며, 우승 업적은 경매 종료 시 별도로 확정됩니다.

준비 화면의 **참가 팀**은 데스크톱 2열과 카드·선수 안쪽 여백을 유지합니다. 왼쪽 참가 팀과 오른쪽 준비 영역의 비율만 1.35:1에서 1.25:1로 소폭 조정했습니다. 선수 사진·이름·Riot ID 아래에 솔로·클랜 티어, 주·부 포지션, 저장된 숙련도 상위 5개를 사진의 왼쪽 끝에 맞춰 배치하며 아이콘은 한 줄로 표시합니다. Riot ID는 한 줄로 표시하고 전체 ID를 툴팁으로도 확인할 수 있습니다. 빈자리 안내와 카드 하단의 별도 5포지션 행은 두지 않습니다.

실제 브라우저에서 팀장 팝업의 **4명 저장·외곽 너비 520px**, 최종 4팀 카드의 왼쪽 정렬·아이콘 5개 한 줄·불필요한 행 제거를 확인했습니다. `화려한솔로#외로운청년`도 실제 팀장 카드에서 말줄임·줄바꿈 없이 표시됐습니다. 최종 575개 전체 회귀도 통과했으며 원격 배포 검수는 별도입니다.

**금액 초기화**는 입찰 입력값만 현재 최고가로 되돌립니다. **경매 초기화**는 주최자·관리자가 환불 미리보기와 사유를 확인한 뒤 낙찰 배정을 되돌리고 순서를 다시 섞는 작업입니다. 참가자·팀장·시작 예산·입찰 시간을 보존하며, 설정 저장 후 준비 상태·진행 중·대진 생성 전 완료 상태에서 사용할 수 있습니다. 대진·경기·우승 보상이 생긴 뒤에는 차단합니다. 초기화·취소 전 입찰은 별도 접힌 기록에 보존하고 새 입찰 효과음에서 제외합니다. [화면·정책 대응표](AUCTION_REFERENCE_MAPPING.md)

일반내전 점수 반영은 **경기 기록 → 일반내전 → 오늘의 10인 내전 → 승리 팀 → 경기 결과 저장**으로 확인합니다. 이 체험 내전은 승리팀 각 +10점, 패배팀 각 −10점입니다. 새로 만든 내전은 생성 당시 점수 정책을 따릅니다. 수기 점수 보정과 업적 지급은 **운영 관리**에서 대상 회원과 사유를 입력합니다.

운영 공간에서는 회원이 직접 가입할 때 계정과 회원을 함께 연결합니다. 매 경매에서 팀장을 지정하면 해당 회원이 본인 계정으로 입찰합니다. 별도 팀장용 계정 발급은 필요 없습니다. 진행자·관리자 권한만으로 다른 팀의 입찰을 대신하지 않습니다.

일반내전·경매 생성은 요청 UUID를 저장하므로 같은 내용의 재전송이 새 내전을 중복 생성하지 않습니다. 명단 확정·회원 변경·결과 저장은 검토 당시 버전을 다시 검사하며, 다른 창에서 바뀐 내용은 최신 정보를 확인한 뒤 저장합니다. 명단·경기와 해당 CSV에는 당시 Riot ID·티어를 보존하고, 현재 회원 정보로 과거 기록을 덮어쓰지 않습니다.

## 주요 기능

| 화면 | 기능 |
| --- | --- |
| 라운지 | 저장된 클랜 소개·롤리몰리 포스터, 경매·일반내전 현황, 최근 경기, 전체 클랜원 검색·최대 480px 내부 스크롤·개인 기록, 관리자 전용 가입 대기 목록 |
| 회원 | 전력점수·일반내전 전적·우승 기호 조회, 검색과 CSV 내보내기, 회원별 기록 |
| 일반내전 | 10명·20명 참가자와 포지션 선택, 자동 밸런싱 또는 수동 팀 배정, 내전 개설 |
| 경매 | 4·6·8팀 경매 생성, 참가 명단·팀장 관리, 팀별 예산·시간 설정, 입찰·자동 마감·낙찰·유찰 재경매·일시정지, 음량 조절, 완료 팀 카드와 대진 준비 |
| 경기 기록 | 일반내전·경매 탭별 대진·명단·전체 경기 이력, 결과 입력·정정, 동률 추가 경기, 종료와 경매 우승 보상 |
| 운영 관리 | 가입 승인·보완 요청·회원 수정·탈퇴·복귀, 점수 보정·업적 지급, 기존 개인계정의 역할·활성 상태·비밀번호 복구, 내부 메모와 감사 기록 |

경매는 4팀에서 풀리그·토너먼트·순위 결정전, 6·8팀에서 풀리그·토너먼트·조별리그와 결승을 지원합니다. 4팀 순위 결정전은 결승과 3·4위전을 모두 진행합니다. 경매 메뉴에서 준비·입찰·대진 확정 후 경기 기록의 경매 탭으로 연결합니다. 라운지와 경매에서 결과를 열면 해당 종류 탭과 경기가 자동 선택됩니다. 각 탭의 선택과 경기 이력은 별도로 유지합니다.

출석은 Discord에서 관리합니다. 앱의 경고는 점수 차감이나 회원 추방을 자동으로 일으키지 않습니다. 참가 제외에는 사유가 필요하며, 허용되는 준비 단계에서 명단을 다시 확정하도록 돌아갑니다. 이전 DB의 출석 자료와 감사 기록은 삭제하지 않습니다.

## 적용 정책

- 일반내전은 실제 확정 경기마다 전원 승리 +10 / 패배 −10이 초기값입니다. 운영진 설정 변경은 **새로 개설하는 일반내전**에 적용되며 기존 내전은 생성 당시 규칙을 유지합니다.
- 기본점수·경기 증감·운영진 보정 원장을 분리합니다. 결과 정정이나 무효 처리로 수기 보정이 지워지지 않습니다. 점수 하한은 두지 않습니다.
- 실제 경기를 각각 기록하고 부전승에는 경기 점수·판수를 부여하지 않습니다. 일반내전 승률에는 확정된 일반내전만 포함합니다.
- 경매 경기 결과는 전력점수에 영향을 주지 않습니다. 경매 종료 시 실제 우승팀 5명에게 4팀은 고양이 1개, 6팀은 별 1개, 8팀은 메달 1개를 각각 지급하며 경매별 중복 지급을 막습니다. 고양이 5개 = 별 1개, 별 5개 = 메달 1개, 메달 5개 = 트로피 1개입니다.
- 경매 참가 명단을 확정할 때 전력점수와 주·부포지션을 저장합니다. 팀장 지정 시 이 전력 스냅샷으로 기본 예산을 계산하며, 시작 전에 운영자가 팀별 예산을 직접 조정할 수 있습니다. 이전·새 예산은 기록하고 회원 전력점수는 바꾸지 않습니다. 경매 시작 후 예산 변경은 거부합니다.
- 입찰은 해당 팀장과 연결된 계정만 할 수 있습니다. 서버에서 중복 요청, 마감 시각, 팀 정원, 잔여 포인트과 입찰가를 검증하고 낙찰 시 잔여 포인트을 반영합니다. 경매 완료 후 대진 확정에는 팀별 5명과 포지션 구성이 필요합니다.
- 시작 시간은 5~30초를 5초 단위로 선택하고 기본값은 10초입니다. 유효한 새 입찰의 마감은 **min(기존 마감 +5초, 서버 현재 시각 +선택 시간)**입니다. 선택한 시작 시간이 연장 후 상한이며, 같은 요청 재전송·거절·마감 후 입찰은 시간을 늘리지 않습니다.
- 낙찰·유찰 후 다음 선수를 준비하는 시간은 3초입니다. 준비·일시정지·정원 완료 상태에서는 입찰을 받지 않습니다. 화면은 자동 갱신하고 수동 새로고침 버튼은 두지 않습니다.
- 풀리그는 승점, 동률 팀 간 승자승으로 순위를 정합니다. 그래도 우승 후보가 동률이면 추가 경기를 치릅니다.

## 결과 정정

관리자는 **진행 중이며 우승 보상을 지급하지 않은 경매 대회**의 확정 결과를 정정할 수 있습니다. 사유와 바꿀 승리팀을 선택하면 무효화되는 후속 경기와 재계산할 대진을 먼저 표시합니다. 미리보기 확인 후 확정해야 실제 기록에 반영됩니다.

원경기는 정정 이력을 추가하고, 이미 완료한 후속 경기는 원장을 `VOID` 상태로 보존합니다. 재경기에는 새 기록을 사용합니다. 더 이상 유효하지 않은 동률 추가 대진은 원본을 보관한 뒤 현재 대진에서 제외하며, 토너먼트·3·4위전·조별리그 결승은 의존하는 결과에 따라 다시 계산합니다. 미리보기 이후 대회 상태가 바뀌거나 10분이 지나면 다시 확인해야 합니다.

종료했거나 우승 보상을 지급한 경매는 이 기능으로 재개·정정하지 않습니다. 일반내전은 기존 결과 정정 흐름을 유지합니다.

## 진행 중 문제가 생겼을 때

- **경매 시작 전 명단·팀장 오류:** 경매의 **참가 명단 다시 준비**에서 사유를 입력합니다. 같은 경매와 명단·기존 감사 기록을 보존하고 팀장·팀별 예산·설정을 다시 준비합니다. 이미 입찰을 시작한 경매에서는 사용할 수 없습니다.
- **팀장 입찰 불가:** 운영 관리에서 해당 승인 회원과 로그인 계정의 연결을 확인합니다. 진행 중이면 일시정지하고 계정 상태를 수정한 뒤 다시 로그인·재개합니다. 일반 참가자에게 입찰 권한을 주는 방식으로 우회하지 않습니다.
- **유찰·접속 장애:** 자동 갱신된 현재 상태를 확인하고 필요하면 개설자·관리자가 일시정지·재개합니다. 유찰 재시작은 현재 라운드 전체가 끝난 뒤 사용합니다. 서버 재시작에는 `run.bat` 또는 `python -m roly.server`를 사용합니다.
- **실제 경기 시작 후 계속 진행 불가:** 관리자는 **경기 기록 → 해당 일반내전·경매 → 취소 → 기록을 보존하고 중단 종료**에서 사유를 남깁니다. 일반내전의 이미 확정된 점수와 경기·경매 낙찰 내역은 유지하고 남은 경기만 중단합니다. 경매 우승 보상은 지급하지 않으며 이미 우승 보상을 지급한 경우에는 사용할 수 없습니다.

정상 흐름과 각 단계의 대체 방법은 [검증·복구 보고서](REVIEW.md)에 정리했습니다.

저장소 선택의 우선순위는 아래와 같습니다. 실행기는 선택한 대상을 화면 프로세스에 그대로 전달합니다. 그 위에 배포 모드 검사를 적용하므로 **`test`/`production` 앱은 SQLite 대상도 거절**합니다. 명시한 `ROLYMOLY_APP_ENVIRONMENT`가 가장 우선하고, 이 값이 없을 때 Supabase 대상 없이 지정한 `ROLYMOLY_DATA_DIR`은 격리 로컬 개발로 판단합니다. 나머지는 `[app] environment`를 읽으며 생략 시 `production`입니다.

| 우선순위 | 조건 | 운영 저장소 |
| --- | --- | --- |
| 1 | `ROLYMOLY_DATABASE_TARGET` 지정 | `supabase://rolymoly` 또는 명시적 개발·검증용 SQLite 파일 경로 |
| 2 | 대상 지정 없이 `ROLYMOLY_DATA_DIR` 지정 | 명시적 개발·검증 예외로 해당 폴더의 `rolymoly.sqlite3` |
| 3 | 위 환경변수 없음 | Supabase 연결 정보를 필수 검증하고 비공개 `rolymoly` 스키마 사용 |
| 중단 | 기본 운영 실행에서 Supabase 설정 없음·빈값·형식 오류 | 오류 표시 후 중단, SQLite로 자동 전환하지 않음 |

Supabase 연결을 지정한 실행은 연결 정보를 일부만 입력하거나 비워도 오류를 표시합니다. 비밀 설정은 프로젝트의 `.streamlit/secrets.toml`을 먼저 읽고, 파일이 없으면 Streamlit Secrets를 읽습니다. SQLite 파일 경로는 상대·절대 경로를 지원하고 URL·SQLite URI는 받지 않습니다. 세부 기준은 [배포 안내](DEPLOYMENT.md)에 있습니다.

`scripts/backup_storage.py`는 PostgreSQL 17 도구로 **앱 스키마 전체 백업과 새 QA 스키마 복원 검증**을 수행합니다. 실제 Supabase의 합성 QA 자료 35개 테이블·20개 sequence 대조를 통과했습니다. 이는 운영 DB를 복원한 결과나 Supabase 프로젝트 전체 백업이 아닙니다. 예약 백업·외부 보관·실패 알림·실제 운영 복원 절차는 남아 있으며, 민감한 원본 백업은 `.data/backups/`에 보관하고 Git/배포 ZIP에서 제외합니다. [백업과 복구 범위](DEPLOYMENT.md#백업과-복구-범위)

Riot 현재 정보는 회원별 수동 갱신 요청으로 조회하도록 연결했습니다. OP.GG 자동 조회와 기존 회원·경기 DB 자동 이관은 연결하지 않았습니다. Riot 갱신은 현재 티어·전적·숙련도 정보를 가져오며, 운영진이 관리하는 클랜 티어·내전 점수와 구분합니다. 기존 코드와 비교 자료는 `.archive/reference-source-20260908.zip`에 보관하며 새 앱에서 불러오지 않습니다. 운영·정책 Markdown 문서는 작업 폴더의 원래 위치에 유지합니다.

## 디자인과 검증

최신 사용자 요청에 따라 기존 화면 구성과 왼쪽 사이드바를 유지하고, 제공한 위밍글 라운지 이미지를 시각 참고로 사용합니다. 라운지는 클랜 소개, 경매·일반내전 현황, 최근 경기, 전력·기록 링크, 실제 클랜원, 관리자 전용 가입 신청을 표시합니다. 모임 일정은 화면에서 제거했습니다. 시각은 한국 시간으로 표시하며 기록이 없으면 빈 상태로 안내합니다.

연분홍 배경·흰 패널·코랄 강조·네이비 본문과 Pretendard 15px을 적용합니다. 페이지 제목은 24px, 버튼은 8px, 입력·회원 아바타는 12px, 회원 카드는 16px, 라운지 패널은 20px 모서리입니다. 전체 클랜원을 최대 480px 내부 스크롤로 표시하며 큰 홍보 문구나 KPI 카드는 추가하지 않습니다.

색상·글꼴·기본 위젯은 Streamlit 테마를 사용하고, `static/app.css`는 지정한 라운지 패널에만 적용합니다. 클랜원 카드는 `roly/member_cards.py`의 스타일이 분리된 Streamlit v2 컴포넌트로 표시합니다. 이름과 포지션·전력, 판수·업적을 왼쪽 정렬한 별도 줄로 두고, 첫 글자 아바타를 사용합니다. MBTI와 개인 소개글은 표시하지 않습니다. 검색 결과는 닉네임순이며 카드 선택 시 해당 회원의 실제 기록을 엽니다. 적용 기준은 [DESIGN.md](DESIGN.md) 맨 위에 기록했고, 그 아래 GoodChoice 원문은 과거 참고 이력입니다.

클랜 소개 이미지는 사용자가 제공한 `rolymoly.png` 원본을 `static/rolymoly-poster.png`로 보관한 한 장만 사용합니다. 이전 포스터와 이미지 선택 항목은 제거했습니다. 포스터를 재생성·합성하지 않으며 날짜·문구만으로 회원·정원·운영 정책을 자동 입력하지 않습니다. [Pretendard 공식 배포](https://github.com/orioncactus/pretendard)의 글꼴과 OFL 라이선스도 `static/`에 포함했습니다.

회원 목록의 **우승 기호**는 실제 업적 원장에서 계산한 🏆 트로피·🏅 메달·⭐ 별·🐱 고양이 개수를 표시합니다. 업적이 없으면 `-`로 표시하며, 전력점수에는 합산하지 않습니다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```
