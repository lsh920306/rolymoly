## 변경과 검사

입찰의 권한·동시성·UUID·서버 마감 판정은 유지하면서 마지막 쓰기와 COMMIT을 하나의 전송 구간으로 묶었다. COMMIT 응답 확인 전에 접수 완료를 반환하지 않으며, 결과가 불확실하면 연결을 폐기하고 같은 UUID로 원장을 확인한다.

실제 서울 PostgreSQL을 사용한 격리 QA 비교는 정상 입찰 100건씩이다. Python 호출→반환 평균은 39.177→29.160ms, p95는 45.575→33.961ms, p99는 48.466→35.903ms, 최대는 51.020→36.581ms였다. 전후 실패·누락·1초 초과는 각각 0건이다. 정상 입찰의 DB 동기화 구간은 3회에서 2회로 줄었다. 이 수치는 Cloud 브라우저의 클릭→확정·상대 화면 지연이 아니다. [검증 범위와 원자료](BID_COMMIT_VERIFICATION.md)

입찰 관련 로컬 검사 221개가 통과했다. 실제 PostgreSQL에서 마감 직전 4팀 경쟁, UUID 동시 재시도, 5초 연장과 상한, 개별 쓰기·COMMIT 실패 시 롤백, COMMIT 후 응답 유실 주입과 원장 재확인을 검증했다. QA 스키마는 검증 후 삭제 확인을 마쳤다.

경매 외에는 Riot 429 응답의 남은 대기 시간이 인증 오류 해제 과정에서 사라지는 결함을 수정했다. 인증 차단 해제는 요청 제한 만료 시각을 유지한다. 두 가지 오류 도착 순서의 신규 검사는 수정 전 모두 실패했고, 수정 후 Riot 집중 검사 38개가 통과했다. 별도 비경매 대표 검사 8개도 통과했다. 일반 내전 생성·팀 변경·결과 정정·종료 및 점수 정합성, 가입 승인 경쟁, 프로필 변경 롤백과 이전 Riot 응답 차단을 포함한다. 이 검사들은 임시 SQLite를 사용했고 운영 설정 읽기와 외부 네트워크를 차단했다.

## 데이터 사용량과 반복 조회

Supabase 관리 화면에서 현재 과금 주기는 2026-09-08부터 2026-10-08까지, 조직 전체 Egress 요약은 3.068/5GB(61%)로 표시됐다. 일별 그래프의 표시값은 9월 8일 417.744MB, 9일 2.157GB, 10일 299.652MB였고 세 날짜 모두 Shared Pooler Egress 100%였다. 따라서 DB 연결의 응답 전송량이 사용량의 출처임은 확인했다. 개별 테스트와 정상·백그라운드 조회의 기여도는 당시 별도 계측이 없어 분리하지 못한다. 프로젝트 필터 화면은 3.234GB를 표시해 조직 요약과 달랐다. 조회·집계 시차가 있을 수 있어 이 차이를 이번 작업의 증가량으로 계산하지 않는다.

이전 80개 브라우저 및 대규모 회귀 검사는 로컬 SQLite를 사용했다. 그 보고서의 로컬 앱 전송량 감소를 Supabase Egress 감소로 해석할 수 없다. 실제 PostgreSQL·Cloud 검증과 원격 DB 조회는 Egress를 사용하지만, 이번 작업에서는 원격 대규모 부하 검사를 반복하지 않는다.

Cloud 실행 경로의 경매 worker는 활성 세션이 없으면 종료한다. READY·PAUSED 및 다음 시각이 없는 WAITING 상태에서는 250ms 후보 조회가 지속될 수 있다. 이 상태만 대기 간격을 늘리는 개선은 후속 후보지만, 경매 시작·재개 시 즉시 깨우기와 마감 동작 검증이 필요하다. 진행 중인 경매에 일괄적으로 느린 조회 간격을 적용하지 않는다. 구독자가 없는 WebSocket room은 DB 조회를 멈추고 만료되며, 구독이 있는 room은 공유 상태 조회를 사용한다.

## 배포 후 확인 범위와 남은 성능 판정

동일 소스의 배포와 공개 화면, 로그인·내 계정, 일반 내전 및 회원·결과 화면 이동을 확인한다. 실제 운영 사이트에서 기존 검증 계정을 사용해 소규모 경매의 입찰 확정·다른 화면 반영·재진입 상태를 점검한다. 생성한 검증용 활동만 삭제하고 회원·계정·Riot·기본 설정 보존을 대조한다. 새 DB 복구 백업은 만들지 않는다.

국내 실제 사용자 평균 60명·최대 80명 조건에서 클릭→입찰 확정 p95 200ms, 다른 화면 반영 p95 300ms, 두 구간 p99 500ms 및 1초 초과 건수·최대 지연은 아직 운영 실측으로 판정하지 않았다. 이번 소규모 운영 확인으로 해당 성능 목표 달성을 주장하지 않는다. 배포 이후 지연 개선은 이 경계를 유지하며 실제 운영 구간을 분리해서 판단한다.
